# 스텔라이브 모바일 정주행 — 단계별 한국어 설치 안내

## 1. 준비와 완성 형태

최종적으로 `https://본인아이디.github.io/stellive-watch/`를 휴대폰에서 엽니다. PC는 최초 저장소 업로드 또는 수정 때만 필요하며, 이후 영상 수집과 사이트 갱신은 GitHub에서 실행됩니다. GitHub Pages는 정적 파일만 제공하므로 개인 기록을 계정 서버에 동기화하지 않습니다.

준비물은 무료 GitHub 계정, YouTube Data API v3를 활성화한 Google Cloud 프로젝트, 해당 프로젝트의 API 키입니다. GitHub 업로드에는 Git 또는 GitHub Desktop을 사용할 수 있습니다. Python은 GitHub가 설치하므로 휴대폰에는 설치할 프로그램이 없습니다.

ZIP을 압축 해제하면 `stellive_watch` 폴더가 나옵니다. **이 새 폴더만 업로드하세요. 기존 프로그램의 config.local.json, SQLite DB, 시청 기록 백업 파일은 업로드하지 않습니다.** 새 ZIP에는 키·원본 DB·개인 기록이 없습니다. dist는 API metadata가 있는 미리보기이며 .gitignore에 의해 Git 업로드에서 제외됩니다.

## 2. 무료 GitHub 저장소 만들기

1. GitHub에서 New repository를 누릅니다.
2. 이름은 `stellive-watch`로 지정합니다.
3. **Public**으로 선택합니다. 무료 Pages와 공개 저장소의 표준 Actions 러너를 사용합니다.
4. 아래 Git 명령으로 업로드할 경우 README·.gitignore·License 자동 생성은 선택하지 말고 Create repository를 누릅니다.
5. 기본 브랜치는 `main`으로 사용합니다. 다른 이름이면 update.yml의 push.branches도 그 이름으로 바꿉니다.

Git이 설치된 PC의 PowerShell에서 압축 해제한 새 `stellive_watch` 폴더로 이동한 뒤 실행합니다. 마지막 URL은 본인 저장소 URL로 바꿉니다.

```powershell
git init -b main
git add .
git status --short
git commit -m "Add mobile Stellive watch site"
git remote add origin https://github.com/YOUR_GITHUB_ID/stellive-watch.git
git push -u origin main
```

git status에서 `.github/workflows/update.yml`, channels.json, scripts/, site/, tests/, README.md, docs/는 올라가고, dist/, .state/, config.local.json과 DB는 없는지 확인합니다. Git 사용자 정보가 없다는 메시지가 나오면 GitHub 계정의 이름과 공개해도 되는 커밋 이메일을 Git 설정에 입력한 뒤 다시 commit합니다. GitHub 로그인은 Git이 여는 인증 창을 사용하세요.

GitHub Desktop을 쓰면 File → Add local repository로 이 폴더를 선택하고, 저장소 생성 안내를 따른 뒤 Publish repository에서 **Keep this code private 선택을 해제**해 공개 저장소로 올릴 수 있습니다. 업로드 후 GitHub에서 `.github/workflows/update.yml`이 실제로 보이는지 확인합니다. 웹 파일 업로드 방식은 dist의 천 개 이상 파일과 숨김 .github 폴더를 실수하기 쉬워 Git 또는 Desktop을 권장합니다.

## 3. Google API와 Secret 설정

1. [Google Cloud Console](https://console.cloud.google.com/)에서 본인의 기존 프로젝트를 선택합니다. 새 유료 서비스나 결제 계정을 만들 필요는 없습니다.
2. APIs & Services → Library에서 **YouTube Data API v3**를 찾아 Enable합니다.
3. Credentials에서 기존 API 키를 사용하거나 Create credentials → API key로 만듭니다.
4. API restrictions는 **Restrict key → YouTube Data API v3**로 제한합니다. Actions의 서버에서 요청하므로 Website/HTTP referrer 제한은 맞지 않습니다. 표준 GitHub 러너는 IP가 변할 수 있어 고정 IP 제한도 사용할 수 없습니다. 키를 공개 코드에 적지 말고 다음 Secret에만 저장합니다.
5. GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret.
6. Name은 정확히 **YOUTUBE_API_KEY**, Secret에는 키 값만 입력하고 Add secret을 누릅니다.
7. 공개 파일, workflow 본문, Pages 설정, 브라우저 JavaScript에는 키를 붙여넣지 않습니다. workflow에는 `${{ secrets.YOUTUBE_API_KEY }}` 참조만 둡니다.

Google Cloud의 API quotas에서 프로젝트의 실제 한도를 확인하세요. 일반 기본 한도는 일일 10,000 units이며 프로젝트마다 실제 부여량과 다른 사용량을 확인해야 합니다. 이 앱은 channels.list/playlistItems.list/videos.list만 사용하고 search.list는 쓰지 않습니다. 각 list 호출은 통상 1 unit이며, 재시도도 요청 예산에 포함합니다. 실행당 최대 1,800회, 예약은 하루 4회이므로 7,200회가 상한입니다. 수동 실행이나 다른 프로그램은 같은 API 프로젝트의 남은 한도를 함께 사용합니다. 할당량이 부족하면 무료 한도를 넘겨 결제하지 않고 중단 후 다음 실행에서 재개합니다.

## 4. GitHub Pages 켜고 최초 실행

1. 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 설정합니다. Deploy from a branch가 아닙니다.
2. Actions 탭에서 **Update archive and deploy Pages**를 선택합니다. Actions 사용 허용 안내가 나오면 허용합니다.
3. Run workflow → main → Run workflow를 누릅니다.
4. Python tests → Browser data logic tests → Restore checkpoint → Collect → Build → deploy 순서로 실행됩니다.
5. 최초에는 Actions 상태 artifact가 없으므로 모든 등록 채널의 공개 uploads를 끝까지 탐색합니다. 채널별로 완주한 목록만 게시하며 예산에 걸린 채널은 다음 실행에 이어집니다.
6. 완료 후 deploy 작업의 github-pages 주소 또는 Settings → Pages의 Visit site를 엽니다.
7. 최초 업로드가 Secret/Pages 설정 전에 실행돼 실패했으면 설정 후 Run workflow로 다시 실행하세요.

workflow는 contents:read, 상태 복원용 actions:read만 수집 작업에 부여합니다. 배포 작업에만 pages:write와 id-token:write를 부여합니다. 저장소 쓰기 권한, 별도 GitHub PAT, YouTube OAuth 로그인은 필요하지 않습니다. 외부 배포는 이 ZIP을 받은 것만으로 자동 시작되지 않으며, 본인 저장소에 올리고 위 설정을 해야 작동합니다.

## 5. 휴대폰에서 시청하기

1. Safari 또는 Chrome에서 **HTTPS Pages 주소**를 엽니다. 메신저 내부 브라우저가 재생을 제한하면 기본 브라우저로 여세요.
2. 일반 영상 또는 가장 오래된 미시청을 선택합니다. 모든 채널의 공개시각이 KST 오름차순으로 합쳐집니다.
3. 영상 제목을 누르면 YouTube 공식 플레이어가 열립니다. 모바일 자동재생이 막히면 플레이어의 ▶ 버튼을 직접 누르세요.
4. 위치는 약 5초 간격과 일시정지·페이지 숨김 때 저장됩니다. 앱 강제 종료에서는 마지막 몇 초가 저장되지 않을 수 있습니다.
5. 마지막 영상 이어보기는 가장 최근에 선택/시청한 미완료 영상을 영상 ID로 찾아 저장 위치에서 엽니다. 새로 발견된 오래된 영상이 끼어도 기존 기록은 바뀌지 않습니다.
6. 가장 오래된 미시청은 전체 포함 목록에서 완료하지 않은 가장 이른 영상을 찾습니다. 채널/검색 필터와 관계없이 전체 정주행 시작점을 찾는 버튼입니다.
7. 영상이 끝나면 완료를 기록하고, ‘끝나면 다음 영상’이 켜져 있으면 현재 보기·채널·검색 조건의 다음 영상으로 이동합니다. 미시청 모드이면 완료 영상은 건너뜁니다. 다른 보기에서는 완료 영상을 수동으로 다시 볼 수 있습니다.
8. 퍼가기/연령/로그인/지역 제한, 오류 100/101/150/153, 플레이어 로딩 실패가 생기면 **YouTube 원본에서 보기**를 누릅니다. 링크에 현재 저장된 재생 위치가 들어갑니다.
9. YouTube 앱/원본 페이지에서 시청한 시간은 자동 동기화되지 않습니다. 돌아와서 시청 완료를 직접 눌러 주세요. 재생 오류 자체는 완료 처리하지 않습니다.

화면 잠금·백그라운드 연속 재생은 모바일 OS/YouTube 정책에 따라 제한됩니다. 이 도구는 그 제한을 우회하지 않습니다. 플레이어 최소 높이 200px와 playsinline을 사용합니다. 기본 브라우저 메뉴의 홈 화면에 추가는 바로가기로 쓸 수 있지만, 브라우저와 홈 화면 실행의 저장 공간이 분리될 수 있습니다. 옮기기 전에 백업하세요.

## 6. Shorts·VOD 분류와 시청 기록

Shorts 여부를 확정하는 공식 Data API 필드는 없으므로 다음 규칙을 사용합니다.

| 자동 후보 | 의미와 처리 |
|---|---|
| 제목 #shorts 또는 shorts 태그 | 제외 후보. 잘못된 경우 수동 포함으로 복구 |
| Shorts 길이 범위 | 검토 필요. 2024-10-14 UTC 이전 공개는 60초, 이후는 180초 기준으로 보수적으로 확인. 길이만으로 제외하지 않음 |
| 제목에 풀영상/다시보기/VOD 표시 | 검토 필요. 설명란의 다른 다시보기 채널 링크로는 분류하지 않음 |
| 라이브 metadata | 검토 필요. 종료된 커버곡·MV 후보는 라이브 정보만으로 VOD로 분류하지 않음. 방송·노래방 제목은 계속 검토 |
| 팬 채널에서 관련 키워드를 찾지 못함 | 검토 필요. 제목·실제 영상 확인 |
| 그 외 | 자동 포함 후보. 내용 확인을 보장하지 않음 |

보기에서 검토 필요·제외됨·전체 영상을 선택해 복구할 수 있습니다. 영상 아래 일반 영상 포함 / Shorts·VOD 제외 / 검토 필요를 누르면 그 기기에 저장됩니다. 자동 판정 복귀는 이 기기의 수동 판정을 취소하고 자동 후보 판정으로 돌아갑니다. **우선순위는 내 브라우저 판정 → 공유 overrides.json → 자동 판정**이며, 내 브라우저에서 자동 판정 복귀를 선택하면 공유 판정도 건너뛰고 자동 후보로 표시합니다.

공유 판정을 적용하려면 ‘공유 분류 내보내기’를 눌러 받은 overrides.json을 저장소의 같은 파일에 반영합니다. 이 파일에는 영상 ID와 include/exclude/review만 있으며 시청 위치·완료 기록이 없습니다. 기존 공유 판정이 있으면 새 파일로 무조건 덮어쓰기보다 ID별 변경을 병합하세요. 커밋하면 재수집·재배포가 실행됩니다.

‘시청 기록 · 백업과 복원’의 기록 백업은 개인 위치·완료·분류를 JSON으로 내려받습니다. 휴대폰 파일 앱/개인 클라우드에 보관하고 공개 저장소에는 올리지 마세요. 다른 기기에서는 기록 복원으로 파일을 선택합니다. 복원은 영상 ID별 최신 기록의 위치와 분류를 병합하고, 어느 쪽에서든 완료한 영상은 완료를 유지합니다. 완료 취소는 해당 영상에서 직접 할 수 있습니다. 여러 탭에서의 실시간 동기화는 최신 기록을 따릅니다.

브라우저 데이터 삭제·비공개 모드·저장 용량 제한·사이트 경로 변경은 기록에 영향을 줍니다. 저장 실패 시 경고가 나며 현재 탭에서 백업할 수 있습니다. 기록 삭제 버튼은 이 사이트 경로의 기록만 지우고 YouTube 계정 기록은 지우지 않습니다.

## 7. 새 채널·과거 영상·활동 기간 수정

channels.json은 JSON 배열입니다. 기존 항목 사이에 아래 구조로 실제 확인한 채널을 추가합니다. 마지막 기존 항목 뒤 쉼표, 새 항목 뒤 닫는 대괄호 위치를 지켜 주세요. 아래 ID는 형식 예시이며 실제 채널로 바꿔야 합니다.

```json
{
  "key": "fan_new",
  "name": "확인한 팬 채널 이름",
  "group": "fan",
  "channel_id": "UC1234567890123456789012",
  "url": "https://www.youtube.com/channel/UC1234567890123456789012",
  "start": "2022-12-20",
  "related_members": ["관련 멤버 이름"],
  "note": "확인 근거와 날짜"
}
```

고유 ID를 모를 때는 channel_id 대신 `"handle":"@실제핸들"`을 사용할 수 있습니다. 최초 수집 뒤 사이트의 채널 상태에 API가 확인한 고유 ID가 나옵니다. 핸들 변경을 피하려면 그 ID로 고정하세요. API가 ID 존재를 확인하는 것과 채널이 공식/주요 팬 채널임을 확인하는 것은 별개입니다.

group은 official/member/fan 중 하나입니다. fan에는 팬 창작과 외부 관련 출처가 있으며 공식 소속을 인증하는 구분은 아닙니다. start와 end는 **KST YYYY-MM-DD 양끝 포함**입니다. 공식 소속으로 공개된 활동의 시작일과 해당 시 졸업일을 적습니다. 이번 목록은 공식 티저 공개일부터 포함해 데뷔 전 공식 커버곡도 수집합니다. 새 채널을 커밋하면 과거 uploads 전체를 탐색합니다. 기존 기간이 바뀌면 진행 중 스캔을 새로 시작하며, 범위 밖 영상은 빌드에서도 즉시 제외합니다. 개인 시청 기록은 ID별로 계속 남아 기간을 복구하면 다시 연결됩니다.

전용 팬 채널은 `relevance`를 생략해 채널 전체를 수집합니다. 여러 대상을 다루는 채널은 `"relevance":"metadata"`를 넣으면 제목·설명·태그에 스텔라이브/정식 멤버명이 있는 영상만 수집합니다. `members`는 제목의 브랜드/정식 멤버명 또는 설명·태그의 정식 멤버명으로 확인하여 반복되는 회사 소개만으로 전체 영상이 포함되는 것을 막습니다. 약칭만 쓰이고 다른 단서가 없으면 혼합 출처에서 빠질 수 있으므로 채널 특성에 맞게 설정하세요. `sources`에는 확인한 채널/영상 링크를 배열로 남길 수 있습니다.

enabled:false는 수집·게시 대상에서 제외하고 채널 정보만 남깁니다. 팬 채널 발견 자체는 수동입니다. 비슷한 내용이라도 **다른 영상 ID는 전부 별개 영상**으로 유지합니다. 같은 ID가 uploads에 중복 노출되는 경우만 한 영상으로 저장합니다.

## 8. 자동 업데이트와 복구

예약은 UTC 00:23/06:23/12:23/18:23, **KST 09:23/15:23/21:23/03:23**입니다. 브라우저가 닫혀 있거나 PC가 꺼져 있어도 실행됩니다. GitHub 스케줄은 정확한 시각·빠짐없는 실행을 보장하지 않습니다.

각 실행은 최근 collector-state artifact를 복원해 소급 수집을 이어갑니다. 정상 완료된 채널만 새 목록으로 교체하며, 페이지 중간 실패는 기존 확정 목록을 보존합니다. 페이지 완료마다 체크포인트를 쓰므로 실행이 강제로 중단돼도 직전 완료 페이지부터 복구할 수 있습니다. 다만 runner 강제 종료로 artifact 업로드 자체가 실행되지 않으면 그 실행의 체크포인트가 전송되지 않을 수 있습니다.

상태 artifact는 **1일** 보관합니다. 그 사이 자동 실행이 모두 실패하거나 artifact를 지우면 다음 실행은 전체 소급 수집을 다시 합니다. 개인 시청 기록은 휴대폰에 있으므로 영향받지 않습니다. 큰 채널에서 일일 요청 예산이 부족하면 다음 실행에 이어집니다. 오래된 pageToken 오류나 1일 넘게 중단된 스캔은 다시 시작합니다.

채널의 전체 수집 성공 시각은 설정 → ‘채널과 업데이트 상태’에서 확인합니다. 목록 생성 시각과 채널 전체 수집 성공 시각은 다릅니다. 395개 활성 출처의 전체 재확인은 한 번의 1,800요청 예산을 넘을 수 있어 여러 실행에 걸쳐 순환합니다. 이전에 확보한 목록은 유지되며 신규·미완료 채널과 오래된 성공 채널부터 진행합니다. 일부 채널 실패가 전체 빌드를 막지 않으므로 GitHub 초록 체크만 보지 말고 사이트의 경고와 채널 상태도 확인하세요.

**월 1회 점검:** Actions 예약이 살아 있는지와 채널 성공 시각을 확인합니다. 공개 저장소는 60일 비활동 시 예약이 비활성화될 수 있습니다. 설정/채널 점검 후 필요한 수정사항을 커밋하고, 꺼져 있으면 Actions에서 Enable workflow 후 수동 실행합니다. 단순 사이트 방문이나 artifact 생성이 저장소 활동을 대신한다고 가정하지 마세요.

YouTube API metadata는 29일 이내 갱신하고 만료분을 수집 상태와 배포에서 제외합니다. 자동화가 완전히 꺼져 있으면 기존 Pages JSON 파일을 원격 삭제할 수 없습니다. **갱신이 29일 넘게 불가능하면 Settings → Pages에서 사이트 게시를 중지하고 배포·Actions artifact를 삭제하세요.** 화면에서 만료 정보를 숨기는 것은 호스팅 파일 삭제와 다릅니다. 내려받은 dist 미리보기도 29일 안에 갱신하거나 삭제하세요.

## 9. 기존 로컬 프로그램 기록 이전 (선택)

이 ZIP의 미리보기는 최신 Actions 수집 상태에서 만든 공개 영상 목록입니다. 개인 시청 기록은 포함하지 않습니다. 원래 프로그램을 계속 사용해 기록이 생겼다면 아래로 옮길 수 있습니다.

1. 이전 프로그램의 서버를 종료합니다. 실행 중 WAL에 남은 쓰기를 놓치지 않도록 먼저 정상 종료하세요.
2. 새 stellive_watch 폴더에서 아래 명령을 실행합니다. DB 경로는 본인 경로로 바꿉니다.

```powershell
python scripts/migrate.py "C:\기존폴더\stellive.sqlite3"
python scripts/build.py
```

3. `.state/stellive-progress-migrated.json`을 휴대폰으로 옮깁니다. Pages 화면의 기록 복원으로 가져옵니다.
4. `.state`와 DB를 GitHub에 업로드하지 않습니다. 새 Actions는 자체 API 수집으로 metadata를 생성합니다. 마이그레이션은 원본 DB를 읽기 전용으로 열고 수정하지 않습니다.

## 10. 문제 해결

| 증상 | 확인·대응 |
|---|---|
| Pages 404 | Source=GitHub Actions, deploy 작업 완료, 저장소 이름 포함 URL인지 확인 |
| Actions에 workflow 없음 | `.github/workflows/update.yml`이 main에 있는지 확인 |
| API 키 없다는 오류 | Secret 이름 YOUTUBE_API_KEY와 Repository secret 저장 위치 확인 |
| HTTP 403 / quotaExceeded | API 활성화·키 API 제한·일일 남은 할당량 확인. 다음 할당량 주기 후 수동 실행 |
| 특정 채널 조회 실패 | 채널 삭제·핸들 변경·고유 ID를 확인. 다른 채널의 metadata는 보존됨 |
| 일부 채널 영상 수 0 | 채널 성공 시각, 소급 수집 진행 여부, 활동 기간, 검토/제외 목록 확인 |
| 새로 공개된 과거 영상 누락 | 다음 전체 uploads 순회에서 반영. 오래된 공개 날짜만 보고 탐색을 조기 중단하지 않음 |
| 삭제·비공개 영상이 잠시 남음 | 해당 채널 전체 순회 완료 때 제거. 기존 개인 기록은 남음 |
| Shorts가 섞임 | 검토·제외·전체 목록에서 수동 판정. 자동 분류는 후보일 뿐임 |
| 자동재생 차단 | 플레이어 ▶ 직접 누르기. 원본 링크 사용 가능 |
| 오류 153 | 브라우저 Referer 차단·확장·내부 브라우저 확인. 기본 브라우저 HTTPS로 열기. 원본 링크 사용 |
| 사이트를 오래 켜두고 이동 실패 | 새 manifest 감지 후 ‘목록 다시 불러오기’ 또는 이동 버튼 재시도. 필요하면 새로고침 |
| 이어보기 사라짐 | 같은 브라우저·같은 URL 경로인지 확인하고 백업 복원 |
| 예약이 멈춤 | 60일 비활동·Actions 정책·한도·Secret 확인. Enable workflow 후 수동 실행 |
| 1일 넘는 중단 후 수집이 오래 걸림 | 상태 artifact가 만료돼 전체 소급 수집 중. 개인 기록은 유지됨 |
| 무료 저장 공간 부족 | 오래된 Actions artifact 정리. 1일 retention 유지. 유료 러너·유료 저장 증설은 사용하지 않음 |

## 11. 공개시각과 채널 정보의 정확도

정렬 기준은 videos.list의 snippet.publishedAt입니다. 처음 비공개로 업로드한 영상이 나중에 공개되면 보통 외부 API에서 제공되는 공개시각을 사용합니다. 비공개 업로드 원시시각을 복원하지 않으며 일부공개·재공개 등 과거 상태 이력까지 완벽히 재구성할 수 없습니다. playlistItems의 목록 추가 시각을 영상 공개시각으로 사용하지 않습니다. 모든 화면과 활동 기간 경계는 KST이며, 동일 초는 영상 ID 순으로 일관되게 정렬합니다.

채널 목록은 기존 파일을 상속했습니다. 2기 일부 활동 시작일의 개별 날짜 미확인 메모 등 기존 불확실성을 유지합니다. 실제 API 검증은 ID/핸들의 조회 및 공개 metadata 수집 검증이며 멤버 소속이나 날짜 전체의 공식 인증은 아닙니다. 최신 멤버/팬 채널을 전수 재조사했다고 간주하지 마세요. [채널목록](채널목록.md)에서 각 설정을 검토하고 필요한 항목을 직접 수정할 수 있습니다.
