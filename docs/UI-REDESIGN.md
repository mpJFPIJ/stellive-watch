# 모바일 UX 개편 설계 · 2026-10-21

목표는 기존 정주행 기능을 모바일 앱처럼 쉽게 이용하는 것이다. 화면 구조를 개편하는 작업이며 사용자의 대폭 개선 요청에 따라 이 세션에서 구현·검증·기존 Pages 배포까지 진행한다. 원본 버전은 Git 이력으로 복구할 수 있다.

## 화면과 시각 방향
- 홈: 큰 타이포그래피, 실제 영상 썸네일과 한 개의 주요 이어보기 동작, 내 시청 현황, 정주행 바로가기.
- 영상: 검색, 빠른 분류 탭, 채널·연도 필터 시트, 날짜 구분과 썸네일 목록. 분류 후보/검토/제외의 차이를 명시한다.
- 기록: 최근 이어보기/완료 목록과 실제 위치. 삭제·비공개 기록도 ID 기반 개인 기록은 유지한다.
- 설정: 화면 모드, 기록 백업/복원, 고급 수동 분류, 채널 상태.
- 재생: 포커스를 가두는 native dialog. 모바일 전체 화면, 데스크톱 집중 창. 닫으면 일시정지·저장하고 이어보기 도크를 남긴다. YouTube 공식 플레이어는 최소 200×200을 지키며 축소하거나 덮지 않는다.
- 밝은 흰색/연회색 표면, 진한 글자, 블루 강조. 동일한 radius·간격·타이포 토큰과 직접 만든 선형 SVG 아이콘. OS/밝게/어둡게 선택, reduced-motion 지원, 44px 이상 주요 터치 영역, 키보드·스크린리더 접근성.

## 보존할 계약
기존 localStorage 키 stellive-watch-v2:{path}, 영상 ID별 기록과 백업 형식, KST 순서, 자동 분류, GitHub Actions 수집과 Secrets를 유지한다. 개인 기록은 서버에 보내지 않는다. YouTube API 키를 클라이언트에 추가하지 않는다. 기존 collector를 변경하지 않는다.

## 파일과 실행 계획
1. core.mjs: 연도 필터·기록 목록 정렬 helpers의 실패 테스트 후 구현. build.py는 분류별 개수를 manifest에 추가한다. Windows에서도 대소문자별 ID가 인덱스에서 덮어써지지 않도록 bucket 경로만 소문자로 합친다. 영상 ID 자체는 바꾸지 않으며 충돌 회귀 테스트를 추가한다.
2. index.html/style.css: 네 화면과 dialog, 공통 디자인 토큰, 모바일·데스크톱 레이아웃을 구현한다. ui.mjs가 표시·탐색·테마를 맡고 app.mjs는 기존 데이터·플레이어 상태를 연결한다.
3. 테스트를 새 사용자 흐름으로 변경하고 기존 위치 저장·재개·원본 링크·분류·탭 동기화·오래된 샤드 회귀 검증을 유지한다. 320/390/430/1024px, 라이트/다크, 키보드 modal, 기존 기록 보존을 검증한다.
4. 독립 코드 검토 후 기존 GitHub Pages에 배포하고 공개 사이트를 재검증한다. 완성 ZIP을 갱신한다.

## 레퍼런스와 적용
- [Toss Design System Mobile](https://tossmini-docs.toss.im/tds-mobile/): 정보 위계, 일관된 컴포넌트와 즉각적인 피드백.
- [Apple HIG Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars): 주요 목적지를 일관된 탭으로 구분한다.
- [Samsung One UI](https://design.samsung.com/global/contents/one-ui/): 보기/조작 영역 구분, 한 손 조작, night mode와 선명한 정보.

브랜드 로고·전용 아이콘·폰트를 복제하지 않는다. 표준 브라우저 기능과 기존 빌드 구조를 사용해 새 제품 의존성을 추가하지 않는다.
